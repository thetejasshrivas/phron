# D18-v1 — PH-19 amount representation and category mapping

**Status:** APPROVED by Tejas, 2026-10-10 IST. The frozen PRD remains unchanged.

The extraction JSON amount is a decimal-rupee string with digits before the decimal point and at most two fractional digits. Convert it deterministically from decimal text to integer paise; reject exponent notation, signs, whitespace, more than two fractional digits, zero, negative values, and values outside the signed PostgreSQL BIGINT paise range. No floating-point conversion is permitted.

Tejas approved the following additional D18-v1 terms on 2026-10-10 IST. The frozen PRD remains unchanged.

1. **Merchant Memory Intercept:** Exact matches in user-scoped local memory route directly to the mapped bucket (standard or custom) with High Confidence before external LLM calls.
2. **Standard Enum Fallback:** For unremembered inputs, the LLM maps to the closest canonical standard bucket enum, or `Unknown` / `Unallocated / Lent`.
3. **Direct Custom Name Matching:** If input text contains the literal name or alias of an active user custom bucket, deterministic classifier maps directly to that custom bucket.
4. **Unknown / Low Confidence Routing:** If an input cannot be mapped with confidence, it routes to Low Confidence (`Needs a Category` card) where user selection saves to merchant memory for future spends.
5. **Provider Verification Disposition:** Offline CI testing relies on the comprehensive 50-case mock corpus, contract tests, and Scenario 18 manual fallback. Live API keys, quotas, and provider retention checks are separated into an isolated manual smoke check without blocking deterministic test runs.
