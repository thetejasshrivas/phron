# D23-v1 — APPROVED — explicit Tejas approval of exact proposed wording, 2026-10-10 IST

Source: PRD §28.1 mobile voice input; §26 outbound extraction-only privacy boundary. Existing microphone focuses text and records no audio.

Exact approved wording:
“P0 voice capture may use browser speech recognition only when the browser explicitly supports on-device processing and an installed recognition language is already available. Require explicit microphone permission and a visible listening/stop state. Do not download recognition models, install tools, use remote browser speech services, or send audio to PHRON, Gemini, Groq or any other provider. Unsupported browsers, unavailable local recognition, denied permission and recognition errors immediately offer text entry without losing existing text. Recognized text is capped at 280 characters and follows the same existing sanitized capture, provider-consent and deterministic mutation boundary; recognition never saves a transaction itself.”

Counterexample: a generic browser speech API can send microphone audio to a remote service even though the financial extraction allowlist authorizes only sanitized spend text. A microphone icon alone is not evidence of working speech capture.

Required tests after explicit approval: unsupported/local-unavailable path makes no recognition or network call; permission denial and recognition errors preserve text; stop/late events cannot submit or overwrite newer input; 280-character bound; visible permission/listening state; ordinary capture boundary retained. Browser evidence must distinguish mocked supported recognition from actual unsupported fallback and must not claim an unseen phone test.
